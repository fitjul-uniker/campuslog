# CampusLog Screen Specification

## 문서 상태

- 현재 화면 기준선은 구현이 완료된 `v1.1 제품 고도화`입니다.
- `2차 MVP 목표` 화면은 로그인·회원가입, 사용자별 DB 저장, AI API 보호와 AI 분석·추천 고도화를 위한 요구사항입니다. localStorage 데이터 이전 화면은 Deferred / Optional입니다.
- Supabase Auth / Postgres, 이메일·비밀번호와 Google OAuth 인증을 2차 MVP 기본 계약으로 사용합니다. 이메일 확인, 비밀번호 재설정, 추가 OAuth provider, AI 모델과 미확정 화면 구성은 별도 결정 전 구현된 것으로 보지 않습니다.
- 모든 화면은 기존 CampusLog의 검정·흰색 중심 브랜드, 넓은 여백과 절제된 표면 스타일을 이어가며, 첫 화면·인증·제품 화면 전체에 쿨 뉴트럴 Liquid Glass foundation을 사용합니다. 세부 시각 기준은 `DESIGN.md`를 따릅니다.

## 공통 화면 요구사항

### 앱 셸과 내비게이션

- `/`의 비로그인 순환 문구·인증 화면과 인증 후 3D 책 표지를 제외한 제품 화면은 공통 앱 셸을 사용합니다.
- 로그인 사용자의 주 내비게이션은 `오늘의 기록`, `나의 활동`, `CampusLog AI`입니다.
- 주 내비게이션을 누르면 목적지 메뉴만 즉시 활성 capsule로 표시하고 이전 메뉴와 이중 선택 상태를 만들지 않습니다. URL 전환 전에는 기존 `aria-current`를 유지하며 완료 뒤 목적지 경로 의미로 갱신합니다.
- 데스크톱은 화면 가장자리에서 분리된 `224px` inset Glass 사이드바를 사용하고, 워드마크를 표면의 가로 중심에 맞추며 현재 메뉴만 같은 표면 안의 capsule로 표시합니다. 861~1179px에서는 `200px` 사이드바와 한 열 콘텐츠 배치를 사용합니다.
- 오늘의 기록·나의 활동·AI 기반 활동 추천의 첫 주요 작업 패널은 달력과 같은 반투명 흰색 64% 표면을 사용해 쿨 canvas가 은은하게 비치도록 하고, 28px blur·hairline·그림자를 공유합니다. 입력과 선택 컨트롤만 더 불투명한 내부 조작 표면으로 구분합니다.
- 데스크톱 좌측 하단에는 얇은 구분선 아래 원형 프로필 사진·닉네임을 표시하고, 계정 드롭다운은 하나의 Glass popover로 사용자 식별 정보, 닉네임 수정과 로그아웃을 제공합니다. 모바일은 같은 메뉴를 44px 원형 아바타 진입점으로 축약합니다. 닉네임 수정은 기존 프로필 위계의 작은 dialog에서 현재 값을 편집하며 1~20자 검증, 저장 중·오류, 닫기·Escape와 트리거 초점 복귀를 제공하고 저장 성공 시 데스크톱·모바일 표시를 즉시 갱신합니다.
- 860px 이하에서는 좌우 safe area 안의 단일 Glass 앱 바에 워드마크, `오늘 / 활동 / AI`, 계정 메뉴를 배치합니다.
- DropdownMenu, Select, Combobox 목록은 기존 portal·positioning·collision·키보드 계약을 유지하면서 공용 Glass popover 재료를 사용합니다.
- FloatingPanel은 dim backdrop 위 하나의 Glass 외곽 재료를 body와 sticky footer가 공유하며 서로 다른 흰 띠로 나누지 않습니다. ExpandableScreen은 전체 화면 크기의 별도 surface를 만들지 않고 최대 760px 중앙 작업 탭 한 면만 짧은 scale·fade로 표시합니다. 활동 추가와 날짜별 기록 작성 탭은 같은 90% 밝은 쿨 표면·28px blur를 사용하고, 입력만 16px near-solid control로 구분하며 취소·저장은 44px capsule을 사용합니다.
- 첫 화면·로그인·회원가입·온보딩과 인증 제품의 상·하위 페이지는 공통 쿨 실버 canvas 위에 놓고 페이지 전체를 별도 웜화이트로 덮지 않습니다. 공개 인증 패널과 입력·목록·상세·결과 내부 작업 공간만 near-solid 표면으로 구분합니다.
- 목록·버튼·입력의 hover, active, selected, disabled와 divider는 공통 쿨 뉴트럴 Liquid 상태 토큰을 사용하고 크림색을 화면별로 직접 지정하지 않습니다. 즐겨찾기 노란 별과 성공·경고·오류는 의미 전달에 필요한 범위에서만 상태색을 유지합니다.
- 활동 상세 메타, 완료 경험 초안, AI 분석, 추천 입력·결과·추천 기록 상세와 경험 작성·수정 폼은 외곽 near-solid 표면 하나가 읽기 배경을 소유합니다. 내부 메타·본문·근거·답변·관련 링크는 투명 배경과 hairline divider를 사용하고, 입력·선택 같은 실제 조작 영역만 공통 control fill로 구분합니다.
- 활동 요약·추천 이미지 업로드·분석 보완 질문의 아이콘은 별도 원형 또는 사각 흰 배경을 만들지 않습니다. 기능 버튼은 최소 44px 조작 영역과 focus-visible을 유지하되 장식용 아이콘 plate는 제거합니다.
- 화면 이동과 중립 저장·수정·완료는 공통 44px Glass capsule과 작은 액션용 얕은 그림자를 사용합니다. 삭제는 글자형 44px 완전 capsule 또는 아이콘형 44px 원형 capsule로 표시하고 글자와 아이콘을 같은 `#b42318` 위험 빨강으로 표시하며 접근성 이름을 유지합니다. `AI 분석` 실행은 같은 완전 capsule 외곽을 사용하되 기존 주황–보라 gradient border·text·icon과 animation을 유지합니다. Dropdown의 삭제 command는 빨강을 공유하되 메뉴 행 구조와 무그림자를 유지합니다.
- 나의 활동과 추천 기록의 즐겨찾기 행은 제목과 44px 별 조작 영역 전체를 하나의 hover·selected 표면으로 표시합니다. 별 버튼은 독립된 조작과 접근성 이름을 유지하되 선택·hover 배경을 분할하지 않으며 본문 버튼에는 별도 border나 inset·drop shadow를 두지 않습니다.
- 활동·추천 기록 스크롤 목록은 상하단 gradient fade를 사용하지 않고 실제 여백과 스크롤 중 transient scrollbar만 사용합니다.
- 인증 제품의 루트 스크롤바는 모든 화면에서 같은 채널 폭과 transient 표시를 사용하며 유휴 상태에는 투명합니다. 문서 전역의 smooth scrolling은 사용하지 않아 메뉴 이동 시 새 화면 상단으로 즉시 정착합니다.
- 추천 기록과 나의 활동 검색은 같은 차콜 Gooey morph를 사용하며, 닫힌 검은 capsule 또는 44px 원형과 열린 검은 검색 필드에서 흰 아이콘·입력값 대비를 제공합니다.
- 모바일에서 핵심 작업을 가리는 고정 요소를 두지 않고, 콘텐츠와 터치 영역이 화면 밖으로 넘치지 않게 합니다.

| 네트워크 오류 | 성공으로 오인시키지 않고 재시도 또는 보존 상태 안내 |

### 접근성과 반응형

- 모든 입력은 보이는 레이블, 오류 연결, 키보드 조작과 명확한 `focus-visible`을 제공합니다.
- 색상만으로 성공·오류·비활성 상태를 전달하지 않고 문구나 의미 있는 구조를 함께 사용합니다.
- 상태 메시지는 필요한 경우 보조기술이 인지할 수 있는 라이브 영역으로 제공합니다.
- 모달이나 패널은 열릴 때 초점 이동, 초점 가두기, `Escape` 닫기와 닫힌 뒤 초점 복귀를 처리합니다.
- `prefers-reduced-motion`에서는 핵심 정보 이해에 필요하지 않은 이동, 부유와 반복 애니메이션을 줄입니다.
- `backdrop-filter` 미지원, reduced transparency, increased contrast와 forced colors에서는 Glass를 불투명 중립 표면으로 대체하며 정보 위계와 조작 영역은 동일하게 유지합니다.

## 현재 구현 화면 기준선

### 1. 상태별 브랜드 진입 (`/`)

**목적**

비로그인 사용자에게 브랜드와 인증 진입을 먼저 제공하고, 인증된 사용자에게 검은 가죽 노트 브랜드 경험을 제공한 뒤 제품 화면으로 진입시킵니다.

**핵심 요소와 동작**

- 비로그인 상태에서는 좌측 상단에 `CampusLog` 워드마크를 고정 표시하고, 첫 viewport 중앙에 `대학생활을 기록하다.` 문구를 가장 먼저 표시합니다.
- 괄호나 네모난 단어 배경 없이 `대학생활을 / 공모전을 / 해커톤을 / 프로젝트를 / 대회를` 순서로 전환합니다. `대학생활`은 진한 검정과 강한 굵기, 나머지 순환 명사는 웜그레이와 한 단계 가벼운 굵기로 표시하되 조사 `을/를`은 항상 진한 검정·강한 굵기로 유지합니다. 기존 명사의 퇴장과 새 명사의 등장을 짧게 교차해 명사가 비는 프레임 없이 실제 글자 폭을 전환하며, 새 단어는 조사 쪽에 붙어 큰 폭 감소에서도 간격이 벌어지거나 기존 단어가 잘리지 않습니다. 조사는 실제 값이 `을 ↔ 를`로 바뀔 때만 별도로 전환하고 문장 전체는 매 상태와 전환 중에 화면 중앙을 유지합니다.
- 문구 아래에는 별도 `일시정지 / 재생` 컨트롤을 표시하지 않습니다. 명사와 조사 사이에는 2~5px 여유를 두고 reduced motion에서는 첫 문구로 고정합니다.
- 스크롤 시 제목은 진행도에 맞춰 부드럽게 사라지고, reduced motion에서는 첫 문구로 고정합니다.
- 첫 viewport의 하단 링크는 테두리·배경·그림자 없이 `스크롤하여 로그인 또는 회원가입` 한 줄과 약하게 움직이는 화살표만 표시합니다. 작은 아래 방향 휠 입력 또는 44px 이상 링크 선택 시 다음 viewport의 로그인·회원가입 영역으로 부드럽게 이동합니다. 인증 화면의 작은 위 방향 휠 입력은 첫 viewport로 자동 복귀시키지 않고 기본 스크롤 거리만 이동하며, 충분히 스크롤해야 첫 화면으로 돌아갑니다. reduced motion에서는 화살표 모션을 정지합니다.
- 인증 영역은 좌측 소개 문구와 구분선 없이 쿨 실버 canvas 위의 단일 frosted Liquid Glass 카드를 중앙에 두고, 로그인과 회원가입 중 하나의 Primary CTA만 표시하며 같은 위치에서 mode를 전환합니다. 로그인 mode에서는 `Welcome back`과 제목 아래 소개 문구를 표시하지 않습니다. blur 미지원·투명도 감소·대비 증가 환경에서는 불투명 흰색 패널로 대체합니다.
- 이메일·비밀번호 등 인증 입력은 흰색 단일 표면, 1px 중립 border, shadow 없음으로 표시하고 focus-visible outline을 유지합니다.
- 인증 성공 후 `/`는 3D 노트를 표시하며, 노트는 장식이면서 `/dashboard` 진입 컨트롤입니다.
- 키보드 초점과 선택이 가능해야 하며, reduced motion에서는 포인터 추적과 반복 움직임을 줄입니다.
- 보호 화면에서 전달된 안전한 `returnTo`가 있으면 책 표지보다 원래 목적지 복귀를 우선합니다.

### 2. 오늘의 기록 (`/dashboard`)

**목적**

진행 활동을 확인하고, 캘린더 날짜에 실제로 한 일을 활동과 연결해 기록하거나 가까운 미래 계획을 미리 작성합니다.

**핵심 요소**

- 오늘 날짜와 `오늘의 기록` 제목
- 활동 현황: 완료 경험으로 저장된 활동을 제외한 진행 중·시작 예정·종료 확인 필요·경험 정리 필요 활동을 하나의 Data Grid에 표시합니다. 열은 pin·활동·상태·시작일·종료일·행 메뉴이며, 행 전체 선택은 `/activities/[id]` 상세로 이동합니다. 상태는 진행 중 초록, 시작 예정 노랑, 종료 확인 필요·경험 정리 필요 빨강 capsule로 표시합니다.
- pin 버튼과 `···` 메뉴의 `상단에 고정/고정 해제`는 선택 행을 고정 시각 역순으로 표 상단에 이동합니다. 핀에는 활동 id·고정 시각만 사용자별 `dashboard_activity_pins`에 저장하고 본인 RLS·활동 삭제 cascade를 적용합니다. 저장 중에는 같은 행의 토글을 비활성화하고 실패하면 낙관적 이동을 되돌리며, 화면 재활성화 시 계정 값을 다시 조회합니다. 메뉴에는 `활동 수정`, `활동 삭제`를 함께 제공하고 Copy ID·새로고침·프로필 이미지는 표시하지 않습니다. 수정은 같은 활동 현황 아래 공용 활동 폼을 열고 삭제는 기존 연결 데이터 확인을 유지합니다.
- 행 hover는 왼쪽 강조선 없이 행 전체 회색 배경만 사용합니다. 고정된 행은 별도 회색 배경이나 pin 버튼 plate 없이 채워진 pin 아이콘으로만 구분합니다. `···` 메뉴는 non-modal로 열어 페이지 스크롤바와 가로 폭을 유지합니다.

- 월간 기록 캘린더와 날짜별 기록 수
- 선택 날짜와 접근 가능한 `+` 기록 액션을 제공하는 날짜별 기록 이벤트 패널

- 진행 활동 핀은 로그인 사용자의 `dashboard_activity_pins`에 활동 id와 고정 시각만 저장하고 `나의 활동` 별 즐겨찾기와 상태를 공유하지 않습니다. 저장 실패 시 상단 이동을 되돌리고 닫을 수 있는 공통 오류를 표시하며 화면 재활성화 시 계정 값을 다시 읽습니다.

- 기록 수정과 삭제는 원래 날짜와 활동 연결을 유지하며 결과를 명확히 알립니다.
- `/activities/new`, `/activities/[id]`, `/experiences/new`, `/experiences/[id]`, `/experiences/[id]/edit`, `/experiences/[id]/analysis`는 `CampusLog`부터 기능 상위 링크와 현재 위치까지 보여주는 Basic Breadcrumb을 H1 시작점 34px 위에 표시합니다. `CampusLog`는 브랜드 Petrona 800, 나머지는 UI 서체를 사용합니다. AI 추천 기록은 `CampusLog > AI 기반 활동 추천 > 추천 기록`을 유지하되 나의 활동과 같은 최대 1120px `primary-page` 프레임을 사용합니다. 860px 이하에서는 동일한 20px/16px gutter를 사용해 단계 수나 화면 종류가 바뀌어도 Breadcrumb과 H1의 x·y 좌표와 타이포그래피가 흔들리지 않게 합니다. 모든 인증 제품 라우트는 콘텐츠 높이와 관계없이 동일한 `thin` 루트 스크롤바 폭을 예약하며, `/experiences`와 `/recommend/history`의 transient scrollbar는 thumb 표시만 바꾸고 레이아웃 채널 폭은 바꾸지 않습니다.

- 링크형 화면 이동, 인라인 `AI 분석 결과`·상세 열기, 중립 저장·수정·완료 실행 버튼은 `추천 기록`과 같은 흰 Liquid Glass capsule을 사용합니다. AI 그라디언트 실행과 삭제·위험·즐겨찾기·검색·닫기·검은 확장 CTA는 고유 의미를 유지하도록 제외합니다.
- 오늘의 기록·나의 활동·AI 기반 활동 추천·추천 기록과 표준 활동/경험 작성 화면은 공통 페이지 헤더 뒤 첫 주요 표면의 workspace anchor를 공유합니다. 861px 이상에서는 같은 1200px 레일 안에서 제목 영역 최소 78px·간격 30px, 640px 이하에서는 16px gutter·제목 영역 최소 99px·간격 30px을 사용합니다. 표준 활동/경험 작성 표면은 읽기 폭을 위한 최대 너비를 유지하더라도 왼쪽 상단 모서리를 이 공통 레일에 맞추고, 첫 주요 workspace와 같은 반투명 64%·28px blur 재질을 사용합니다. 860px 이하 AI 추천의 추천 기록 이동은 헤더 흐름 밖 우측 액션으로 두고, 640px 이하에서는 44px 아이콘으로 축약하되 링크의 접근 가능한 이름을 유지합니다. 추천 기록의 모바일 gutter도 다른 화면과 같은 20px/16px을 사용합니다. 상세 제목이나 상태·액션이 이 최소 높이보다 커지면 잘림 없이 자연 높이로 확장합니다.

### 3. 활동 추가 (`/activities/new`)

**목적**

앞으로 진행하거나 현재 진행 중인 활동의 최소 정보를 등록합니다.

**입력**

- 활동 제목
- 활동 정보
- 시작일
- 예상 종료일: 날짜 또는 `미정`
- 시작일과 예상 종료일 입력은 같은 상단선에 정렬합니다. 예상 종료일은 하나의 컨트롤 안에서 날짜와 오른쪽 `미정` 영역을 구분선으로 나누며, `미정`은 24px 체크박스로 선택합니다.

**동작과 상태**

- 미래 시작일은 시작 예정, 오늘 또는 과거 시작일은 진행 중으로 등록합니다.
- 예상 종료일은 시작일보다 빠를 수 없습니다.
- 대시보드에서는 대형 둥근 확장 작성 패널로 열고 저장 CTA를 아이콘 없는 `저장`으로 표시하며, 직접 URL·새로고침을 위한 `/activities/new` 페이지도 같은 공용 폼과 validation을 사용합니다.
- 대시보드의 `저장` 또는 직접 페이지의 `활동 저장` 성공 후 생성한 활동 상세로 이동합니다.
- 필수값, 날짜 관계와 저장 오류를 필드 또는 폼 수준에서 안내합니다.

### 4. 진행 활동 상세 (`/activities/[id]`)

**목적**

활동 상태, 기간과 날짜별 기록을 확인하고 활동 시작·종료와 완료 경험 생성을 수행합니다.

**핵심 요소**

- 제목, 상태, 활동 기간, 기록된 날과 누적 기록
- 상태는 활동 현황과 같은 점·outline capsule을 사용합니다. 진행 중은 초록, 시작 예정은 노랑, 종료 확인 필요와 경험 정리 필요는 빨강이며, 종료 후 완료 경험 저장 전 활동은 `경험 정리 필요`로 표시합니다. 같은 상태 배경·테두리·글자색을 나의 활동의 진행 활동 목록과 열린 상세에도 적용합니다.
- 활동 타임라인
- 시작 예정 활동의 시작 액션
- 진행 활동의 `오늘 한 일 기록하기`, `활동 종료`
- AI 처리, 실패, 초안 검토와 완료 경험 저장 상태

**활동 종료 흐름**

1. 종료 확인에서 연결 기록 수와 AI 초안 생성 사실을 설명합니다.
2. 기록이 없으면 종료하지 않고 기록 보완을 안내합니다.
3. AI는 날짜별 기록을 근거로 활동 내용, 성과와 근거 부족 정보를 정리합니다.
   - 미래 날짜의 계획은 화면과 저장소에 보존하되 완료 경험 합성 입력과 기록 수·분량 계산에서 제외합니다.
4. 사용자가 초안을 확인·수정한 뒤 `나의 활동`에 저장합니다.
5. 실패 시 활동 다시 열기 또는 AI 재시도를 제공하고 원본 기록을 보존합니다.
- AI 합성 초안 헤더와 제목·활동 정보·기간 메타 사이의 중복 가로선은 표시하지 않습니다. 주요 성과는 textarea placeholder로 입력 방식을 안내하고 같은 의미의 하단 보조 문구를 반복하지 않습니다.

### 5. 나의 활동 (`/experiences`)

**목적**

진행 활동과 완료 경험을 한 목록에서 탐색합니다.

**핵심 요소와 동작**

- 페이지 H1 `나의 활동`과 설명은 목록 Glass 밖의 공통 페이지 헤더에 표시합니다. 목록 Glass는 H2 `전체 활동`, 개수와 검색부터 시작해 페이지 제목과 탐색 섹션을 구분합니다.
- 등록된 활동이 없으면 가운데 장식용 `+`를 표시하지 않습니다. 데스크톱 빈 상태는 목록 헤더 아래 남은 패널 높이를 채워 하단에 어중간한 공백을 만들지 않고, 모바일은 최소 260px 안에서 제목·설명·액션을 중앙 정렬합니다. `과거 경험 기록하기`는 44px 완전 Glass capsule과 오른쪽 화살표를 사용하며 우측 하단의 전역 추가 버튼과 역할을 구분합니다.
- 전체 활동 수와 진행 중 활동 수
- 제목 검색
- 완료 경험과 진행 중인 활동 행의 44px 별을 선택하면 노란색으로 채워지고 항목이 같은 목록 상단의 `즐겨찾기` 구획으로 이동하며, 나머지는 `모든 활동` 아래에 표시됩니다. 해제하면 연한 회색 별과 일반 목록으로 돌아오고 같은 항목을 두 구획에 중복 표시하지 않습니다. `즐겨찾기`와 `모든 활동` 제목은 목록 폭이나 구획 높이가 바뀔 때 글자를 늘이거나 누르지 않고 위치만 이동합니다.
- 별 토글은 상세 선택 버튼과 분리하고 `aria-pressed`, 활동명을 포함한 추가·제거 이름, 저장 중 비활성 상태와 키보드 focus를 제공합니다. 즐겨찾기 정보는 로그인 사용자의 `favorite_items`에 완료 경험 또는 진행 활동 유형·id·선택 시각만 저장해 다른 기기에서도 다시 불러오며, 저장 실패 시 낙관적 이동을 되돌리고 목록 위에 닫을 수 있는 안내를 표시합니다. 기존 사용자 scope의 브라우저 즐겨찾기는 DB 병합 성공 뒤 해당 범위만 정리합니다.
- 별 토글은 원형 테두리·배경과 아이콘 외곽선을 표시하지 않고 채움색만 사용합니다. 키보드 `focus-visible`에서는 조작 위치를 잃지 않도록 별도의 포커스 링을 유지합니다.
- `나의 활동` 화면 제목은 좁은 폭에서도 가로 한 줄을 유지합니다. 목록 패널이 좁아지면 검색을 아이콘으로 축약하고 최소 폭에서는 활동 수 배지를 숨깁니다. 모바일에서 닫힌 검색은 `전체 활동` 행 오른쪽의 44px 아이콘으로 고정합니다. 펼칠 때도 페이지 H1은 유지하되 목록 헤더의 활동 수와 `진행 중` 배지만 잠시 숨기고, 같은 높이에서 H2 오른쪽의 남은 폭 안에 최대 250px 검색창을 표시합니다.
- 나의 활동 검색은 목록 Glass의 clear capsule이 아니라 기존 차콜 Gooey 표현을 사용합니다. 닫힘은 검은 원형과 흰 검색 아이콘, 열림은 검은 검색 필드와 왼쪽 원형으로 전환하며 입력 자동 초점, Escape, 검색어 지우기와 닫기 동작을 유지합니다.
- 진행 활동은 예상 종료일까지 `진행 중`, 예상 종료일 다음 날부터 `종료 확인 필요`로 표시합니다. `종료 확인 필요`는 자동 종료가 아니라 사용자가 실제 종료 여부 또는 활동 기간을 확인해야 하는 화면 상태이며, 저장된 활동 status를 임의로 변경하지 않습니다.
- 진행 활동 상세는 완료 경험 상세와 동일한 내부 스크롤·안전 여백 구조를 사용하며, 좁은 데스크톱 슬롯에서도 콘텐츠와 하단 액션이 외곽 모서리에 잘리지 않습니다.
- 선택 후 목록을 유지하는 상세 패널
- 선택된 활동 행은 별도 흰색 카드·drop shadow 없이 목록 안의 옅은 차콜 틴트와 2px 왼쪽 인디케이터로 표시합니다. 키보드 focus-visible은 기존 outline을 유지하며 모바일에서는 인디케이터와 제목·상태 배지가 겹치지 않도록 안쪽 여백을 유지합니다.
- 데스크톱에서 좌측 목록 패널과 우측 완료 경험 상세 패널은 다른 주요 작업 탭과 같은 54% frosted 외곽 배경, 28px blur, hairline과 외곽 그림자를 사용합니다. 두 패널은 배경색을 달리하지 않고 목록의 선택 상태와 상세의 콘텐츠 위계로 역할을 구분하며 기존 radius·모바일 세로 배치는 유지합니다.
- 우측 완료 경험 상세는 하나의 frosted Glass 표면으로 표시합니다. 활동 기간과 역할은 한 행에 병렬 배치하지 않고 각각 전체 폭의 독립 행으로 표시하며, 활동 내용·성과·링크·첨부 파일은 같은 hairline 구분 리듬을 사용합니다. 첨부 파일은 별도 흰 카드로 감싸지 않고 관련 링크와 같은 행 높이·leading preview·모서리·hover를 사용합니다. 상세 내부와 하단 액션 영역에는 별도 흰색·회색 배경이나 inset shadow·backdrop blur를 중첩하지 않고 투명 배경을 유지합니다. 상세 외곽 경계·그림자·스크롤과 버튼 상태는 유지하며 AI 분석 패널의 내부 표면은 변경하지 않습니다.
- 완료 경험 인라인 상세의 첫 번째 주요 액션으로 `활동 상세 보기`를 표시하며, 선택하면 `/experiences/[id]` 독립 상세로 이동합니다. 하단에는 `활동 상세 보기`, `수정`, 휴지통 아이콘과 `삭제`, `AI 분석 요청` 또는 `AI 분석 결과`를 순서대로 제공합니다. 삭제는 연결 분석·추천 데이터가 함께 정리됨을 확인한 뒤 실행하며, 성공하면 목록에서 제거하고 상세를 닫고 실패하면 현재 목록과 상세를 유지합니다. 목록과 상세가 좌우로 놓이고 실제 상세 슬롯 폭이 560px 이하이면 네 액션을 조밀한 한 줄로 유지합니다. 저장된 `AI 분석 결과`를 선택하면 같은 `/experiences` 화면에서 목록을 접고 활동 상세를 왼쪽, 분석 결과와 부족 정보 답변 카드를 오른쪽에 1:1 동일한 폭으로 표시합니다.
- 분석 스플릿뷰를 닫으면 기존 목록·상세 구조로 돌아가고 실행한 `AI 분석 결과` 버튼으로 초점을 복귀합니다. 인라인 활동 상세의 `X` 또는 `Escape`를 누르면 현재 우측 슬롯에서 오른쪽으로 퇴장한 뒤 선택을 해제하고 목록을 확장합니다. `Escape`는 분석 패널을 먼저 닫고, 분석 패널이 없을 때 활동 상세를 닫습니다.
- 데스크톱 활동 선택 전환은 목록의 왼쪽 기준점을 고정한 실제 폭 축소와 패널 간격 열림을 0.42초 동안 함께 보간하고, 상세는 0.08초 뒤 오른쪽 32px에서 0.34초 동안 진입합니다. 목록 표면과 글자를 transform scale로 누르지 않으며 모바일에서는 폭 전환 없이 기존 세로 배치를 사용합니다. reduced motion에서는 폭·위치 이동을 제거하고 짧은 fade만 제공합니다.
- 분석 패널은 추천 기록 상세와 같은 frosted 외곽 Glass 한 면을 사용합니다. 헤더에는 분석 생성일을 먼저 표시하고, 왼쪽 활동 상세와 중복되는 활동명 대신 `AI 분석 결과`, 분석 상태와 닫기 액션을 표시합니다. 헤더는 sticky로 고정하지 않고 패널 콘텐츠와 함께 스크롤합니다. 861px 이상에서는 전체 활동·상세와 같은 페이지 잔여 높이를 채워 하단을 좌측 메뉴와 맞추고, 분석 상태에서 남는 상세 슬롯은 표시하지 않습니다. 외곽 Glass는 고정하고 내부 `.dashboard-analysis-split-scroll`만 스크롤하며, 내부 스크롤 구간은 외곽 위·아래에서 30px 안쪽에 배치합니다.
- 부족 정보의 닫힌 행에는 질문 전체를 미리 반복하지 않고 분류명과 답변 상태만 표시합니다. 행을 열면 실제 질문을 입력창 위에 한 번 표시하고, 입력창 아래 보완 이유는 별도 색면 카드가 아닌 border 없는 중립 안내로 제공합니다.
- `/experiences`의 스크롤바는 투명 트랙을 유지하되 페이지와 패널의 위계를 나눕니다. 페이지는 8px 채널 안의 2px·24% 캡슐, 활동 목록·우측 상세·분석은 10px 채널 안쪽의 3px·30% 캡슐을 실제 스크롤 중에만 표시하고 마지막 이벤트 650ms 후 숨깁니다. 우측 활동 상세와 AI 분석 결과는 둥근 외곽 표면과 실제 스크롤 viewport를 분리해 Chromium thumb가 반응형 24~28px 모서리·외곽선에 진입하지 않게 합니다. 숨겨진 상태의 hover만으로 드러내지 않으며, 표시된 thumb의 hover·drag에서만 44%·56%로 진하게 해 직접 조작 가능성을 알립니다. 안정적인 채널로 표시 전후 콘텐츠 폭을 유지하고 reduced motion에서는 색 전환을 80ms로 줄이며 forced colors에서는 시스템 스크롤바를 숨기지 않습니다.
- 분석 패널 하단에는 `/experiences/[id]/analysis`로 이동하는 진한 `분석 상세 보기`와 오른쪽 화살표를 먼저 표시하고, 그 오른쪽에 `다시 분석하기`를 배치합니다. 520px 이하에서는 두 버튼을 전체 폭 세로 구조로 전환합니다.
- 과거 경험 기록 진입점
- 진행 활동은 `/activities/[id]`, 완료 경험은 `/experiences/[id]`로 연결합니다.
- 완료 경험의 첨부 사진과 PDF 자료가 있으면 인라인 상세에서 파일명·종류·크기와 사진 썸네일을 표시하고 새 창에서 원본을 확인할 수 있습니다. 첨부 구획은 별도 흰 카드로 중첩하지 않고 관련 링크와 같은 투명 section·hairline 및 동일한 행 밀도를 사용합니다.
- 모바일에서는 목록 위, 상세 아래 구조를 사용하며 분석을 열면 활동 상세 다음에 분석 결과를 세로로 배치합니다. 상세를 닫으면 선택 항목으로 초점을 돌려줍니다.

### 6. 과거 경험 작성·수정 (`/experiences/new`, `/experiences/[id]/edit`)

**목적**

이미 끝난 프로젝트, 공모전, 인턴과 대외활동 경험을 직접 작성하거나 수정합니다.

**입력**

- 제목, 기간, 역할, 활동 내용, 성과
- 관련 링크 URL과 설명
- 사진 첨부와 PDF 자료 첨부. 합계 최대 3개, 파일당 5MB

**동작과 상태**

- 작성·수정 화면에서는 AI 분석을 실행하지 않고 경험 저장에 집중합니다.
- `활동기간`은 제목·역할·활동 내용과 동일한 0.88rem·muted 색·800 굵기의 필드 제목으로 표시합니다. `시작`·`종료`만 0.75rem·tertiary 색·700 굵기의 보조 label로 한 단계 낮춰 위계를 구분하고, 필드 제목 아래에는 10px 여백을 둡니다. 빈 month 입력의 브라우저 기본 `----년 ---` 대신 `연도와 월 선택`을 표시하고, 선택하면 `YYYY년 M월`, 현재 진행 중인 종료 입력은 `진행 중`으로 표시합니다. 실제 native month input과 달력 아이콘·키보드·label 연결은 유지하고 별도 기간 예시 문구는 표시하지 않습니다. `현재 진행 중`은 24px 체크박스와 최소 44px 라벨 클릭 영역을 사용합니다.
- 경험 입력과 AI API는 제목 200자, 역할 1,000자, 내용 8,000자, 성과 4,000자의 공통 상한을 사용합니다. 내용과 성과의 글자 수는 평소 표시하지 않고 각 상한의 90%부터만 입력창 아래에 안내합니다. 초과 붙여넣기는 조용히 잘라내지 않고 원문을 유지한 채 초과 분량과 줄여야 할 글자 수를 인라인으로 표시하며, 저장 시 해당 입력으로 초점을 이동합니다.
- 역할 입력은 여러 줄을 수용하도록 전체 폭의 3줄 textarea와 최소 96px 높이를 사용합니다. 본문 입력 label은 `활동 내용`으로 표시합니다. 링크 형식, 빈 URL에 입력된 설명과 중복 URL을 검증합니다. `관련 링크` legend는 역할·활동 내용·성과 label과 같은 왼쪽 기준선·타이포그래피·8px 간격을 사용하며, 목적을 반복하는 설명 문장은 표시하지 않고 최대 10개 안내만 유지합니다. 관련 링크의 `URL`·`설명 (선택)` 열 제목은 첫 행에만 표시하고, `URL` 제목은 링크 아이콘이 아닌 폼 본문의 왼쪽 기준선에 맞춥니다. `링크 추가`는 아이콘과 글자가 함께 있는 44px 완전 Glass capsule을 사용하고, 삭제는 입력 중심선에 맞춘 44px 빨간 원형 capsule로 표시합니다. 추가 행에는 입력창과 삭제 동작만 반복하되 각 입력의 접근 가능한 이름은 유지합니다. 링크 행 사이에는 구분선을 두지 않고 좁은 간격으로 묶습니다.
- 사진은 JPG·PNG·WebP, 자료는 PDF만 허용하며 빈 파일과 5MB 초과 파일은 저장 전에 안내합니다. `첨부 파일` 제목과 점선 dropzone은 활동 내용·성과의 label-control과 같은 8px 간격을 사용하고, 첨부가 AI 분석에 사용되지 않음을 표시합니다. ReUI `Table file upload`를 참고해 단일 점선 drag and drop 영역과 그라데이션 없는 단색 차콜 `파일 선택`을 제공하고, 선택 파일은 이름·형식·용량·삭제 동작이 있는 Table로 표시합니다. 상단에는 전체 삭제만 제공하며 모바일에서는 파일명 아래에 형식·용량을 합쳐 가로 overflow를 만들지 않습니다.
- 저장 후 완료 경험 상세로 이동하며, 기존 분석과 원본이 달라지면 업데이트 필요 상태를 표시할 수 있습니다.
- 데스크톱 경험 작성·수정 화면은 독립 경험 상세와 같은 폭·헤더·본문·액션 기준선과 스크롤 형식을 사용합니다. 수정 헤더 우측에는 `경험 상세` 복귀 버튼을 두고, 두 폼 모두 외곽 탭 하단을 좌측 메뉴 하단에 고정합니다. 내부 스크롤 시 Breadcrumb·H1이 함께 사라지면서 탭 상단이 좌측 메뉴 상단까지 확장되고, 하단 저장·수정 완료·취소는 상세 하단 액션과 같은 왼쪽 기준선과 안전 여백을 사용합니다. transient scrollbar 채널은 외곽 곡률에서 좌우 8px 안쪽에 두고 본문 x축은 유지해 thumb가 모서리에 잘려 보이지 않게 합니다. 저장은 단색 검정 capsule이며 저장·취소 hover는 크기나 위치를 바꾸지 않습니다. 선택 파일 목록 상단에는 중복 `파일 추가`를 표시하지 않고 dropzone의 `파일 선택`과 drag and drop으로 파일을 더합니다. 모바일에서는 기존 문서 흐름을 유지합니다.

### 7. 완료 경험 상세 (`/experiences/[id]`)

**목적**

경험 원본과 분석 상태를 확인하고 수정·삭제·AI 분석으로 이동합니다.

**핵심 요소와 동작**

- Breadcrumb 아래에 H1 `경험 상세`와 저장한 경험의 내용·성과·AI 분석을 확인한다는 설명을 표시합니다. 상세 Glass 안의 경험명은 H2로 두어 페이지와 콘텐츠 위계를 구분하고, `나의 활동`은 헤더 오른쪽 복귀 버튼으로 제공합니다.
- 861px 이상에서 Breadcrumb·H1·설명의 최초 위치는 나의 활동 목록의 공통 페이지 헤더 기준선과 일치합니다. 상세 Glass는 나의 활동·오늘의 기록 주요 탭과 같은 공통 콘텐츠 레일 전체 폭을 사용하고 하단을 좌측 메뉴 하단에 항상 고정합니다. 하단은 두꺼운 여백 띠 없이 1px hairline과 32px 곡률로 닫고 스크롤 트랙은 위아래 24px 안쪽에 두며, 내부 transient viewport는 상세 본문과 하단 액션을 소유합니다. 콘텐츠에는 30px top·30~40px inline 안전 여백을 적용하고 마지막 액션 아래 scroll padding은 기본 30px에 도입부 최대 이동량을 처음부터 더해, 스크롤 중 전체 길이가 변하지 않고 끝에서도 버튼이 잘리지 않게 합니다. 860px 이하는 가로 overflow 없는 자연스러운 문서 흐름을 유지합니다.

- 기간, 역할, 내용, 성과, 관련 링크와 첨부 파일
- 공통 콘텐츠 레일 전체 폭의 단일 frosted Glass 표면 안에서 분석 상태 → 제목 → 기간·역할 → 본문 구획 → 액션 순으로 표시합니다. 내부 섹션은 별도 흰 카드로 나누지 않고 투명 배경과 hairline을 사용하며 링크·첨부·태그·하단 액션은 공통 44px 높이·12px 모서리의 쿨 뉴트럴 Liquid control로 통일합니다. 삭제는 텍스트가 아닌 휴지통 아이콘만 빨강으로 표시합니다. 640px 이하에서는 카드 곡률과 좌우 padding을 줄이고 한 열 메타를 유지해 가로 잘림 없이 문서 전체를 자연스럽게 스크롤합니다.
- 사진은 관련 링크 favicon과 같은 36px 정사각형 썸네일, PDF는 같은 크기의 자료 아이콘으로 표시해 새 창에서 확인합니다. 파일 행은 관련 링크와 같은 10px 모서리·11px 12px padding·중립 hover를 사용하며, 독립 상세에서는 오른쪽의 빨간 원형 삭제 버튼으로 개별 첨부를 삭제할 수 있습니다.
- 수정, 삭제, AI 분석 요청 또는 분석 결과 액션
- `/experiences` 인라인 상세의 분석 결과 액션은 별도 라우트 이동 대신 스플릿뷰를 열고, 직접 URL로 진입한 `/experiences/[id]`는 기존 상세 fallback을 유지합니다.
- 삭제 전 확인을 거치며 연결 데이터 처리 정책은 2차 MVP DB 설계와 일치시킵니다.

### 8. AI 경험 분석 (`/experiences/[id]/analysis`)

**목적**

특정 완료 경험의 AI 분석 결과를 보여줍니다.

**최소 출력 계약**

- 경험 요약
- STAR 구조
- 주요 성과
- 부족한 정보와 카드 안 직접 답변 입력 / 저장
- 활용 가능한 키워드
- 분석 생성일
- 분석 최신 여부

**동작과 상태**

- `/experiences`에서 저장된 결과를 선택하면 같은 화면의 오른쪽 분석 패널에 이 출력과 부족 정보 답변 카드를 표시합니다. `/experiences/[id]/analysis`는 직접 진입과 기존 링크 호환을 위해 유지합니다.
- 독립 분석 화면은 분석 생성일 아래에 경험 제목을 대표 제목으로 표시하고, 스플릿뷰는 같은 메타 아래 `AI 분석 결과`를 제목으로 표시합니다. 정상 상태에서는 반복 사용법 notice를 표시하지 않고 원본 경험 수정 또는 레거시 재분석 상태처럼 사용자의 조치가 필요한 안내만 조건부로 표시합니다.
- 미분석, 분석 중, 분석 완료, 업데이트 필요와 실패 상태를 구분합니다.
- 부족 정보 답변 UI는 답변 없음, 답변 작성 중, 저장 중, 저장 완료, 저장 실패, 기존 답변 수정 상태를 구분합니다.
- 부족 정보는 질문별 흰색 `MorphSurface`로 표시하고 한 번에 하나만 펼칩니다. 닫힌 질문은 원형 상태 아이콘·분류·한 줄 질문·답변 여부·Chevron을 표시하고, 펼친 질문은 같은 표면 안에서 전체 질문, placeholder 없는 답변 textarea, 제목 없는 Warning Alert의 분석 사유, 글자 수·차콜 저장 액션 순서로 표시합니다. Alert는 경고 아이콘과 기존 사유 문장만 `role="note"`로 제공하며 답변 입력창 아래에 둡니다. 기본 `답변 없음`과 노출형 Command/Ctrl+Enter 안내는 표시하지 않고, 저장·작성·오류처럼 의미 있는 상태 문구만 조건부로 표시합니다. 질문 표면은 16px 간격을 유지하고 열린 표면 전체를 이전 질문 방향으로 translate하지 않습니다.
- 질문을 열면 표면 상단을 고정한 채 reveal 높이가 0에서 자연 높이로 확장되고, 본문은 아래 12px에서 원위치로 올라옵니다. 새 질문의 열림에는 짧은 지연을 두어 기존 질문 닫힘이 먼저 시작되게 하며, 인접 질문은 scale 변형 없이 reveal 높이에 따라 위치만 이동합니다. 해당 textarea로 초점을 이동하되 분석 스플릿 패널의 스크롤을 강제로 바꾸지 않습니다. 바깥 클릭 또는 Escape로 질문만 닫고 원래 질문 trigger로 초점을 복귀하며, Command/Ctrl+Enter는 현재 답변 저장을 실행합니다. 빈 답변·저장 실패에서는 입력과 열린 상태를 유지하고 저장 성공 뒤에만 닫습니다. 모바일에서는 추가 translate를 사용하지 않고 reduced motion에서는 높이·이동·spring을 제거합니다.
- 보완 답변 저장은 원본 경험을 자동 수정하지 않고, 추천 / 답변 초안 입력에는 즉시 반영합니다. 요약과 STAR까지 갱신하려면 다시 분석합니다.
- 다시 분석할 수 있고, 실패 시 원본 경험과 마지막으로 저장된 유효 결과를 임의로 삭제하지 않습니다.
- 독립 분석 화면은 Breadcrumb, `분석 결과` H1·설명, `활동 경험 상세로 돌아가기`, `나의 활동으로 돌아가기`를 결과 표면 밖의 페이지 도입부로 표시합니다. 861px 이상에서는 결과 표면 하단을 좌측 메뉴 하단에 항상 고정하고 하단은 두꺼운 여백 띠 없이 1px hairline과 32px 곡률로 닫으며, 스크롤 트랙은 위아래 24px 안쪽에 두고 내부 transient viewport는 분석 결과 전체를 스크롤합니다. 마지막 footer 아래 scroll padding은 기본 30px에 도입부 최대 이동량을 처음부터 더해 스크롤 범위를 고정하고, 끝까지 스크롤해도 액션이 하단 곡률에 가려지지 않게 합니다. 결과 헤더와 첫 `경험 요약` 사이에는 중복 가로선을 두지 않습니다. 저장된 결과의 `다시 분석하기`와 실행 오류는 결과 카드 밖에 분리하지 않고 활용 가능한 키워드 다음 hairline으로 구분한 같은 흰 표면의 footer에 왼쪽 정렬하며 `AI 기반 활동 추천` 링크는 표시하지 않습니다. 분석 결과가 없을 때도 같은 구조를 사용하고 상세 패널 내부 하단에는 별도 외부 여백 없이 `AI 분석 요청`만 표시합니다.
- 독립 분석 결과를 아래로 스크롤하면 패널 밖의 도입부와 분석 본문이 같은 속도로 올라갑니다. 도입부가 완전히 사라진 뒤 결과 표면 상단은 좌측 메뉴 상단에 맞춰 멈추며, 결과 표면 하단은 초기·이동 중·상단 도달 후 모두 좌측 메뉴 하단과 같은 위치를 유지합니다.

- 헤더의 `추천 기록`은 History 아이콘을 포함한 기존 ghost 링크와 기존 반응형 배치로 이전 결과를 확인합니다. 현재 추천 화면을 반복하는 활성 탭이나 전역 내비게이션과 중복되는 `나의 활동` 바로가기는 표시하지 않습니다.

- 활용 목적별 예시 문항은 면접, 자기소개서, JD 분석, 기타에 각각 대표 6개만 제공합니다. 면접과 자기소개서는 전공과 관계없이 역할·성과·문제 해결·협업·주도성·성장을 연결할 수 있는 질문을 사용하고, 기타는 포트폴리오·이력서·1분 자기소개·대외활동·발표·전공과 직무 연결을 다룹니다. JD 분석은 모든 직무에 쓸 수 있는 핵심 요약·요구사항 비교·적합 경험·지원 전략과 함께 플랫폼·결제 서버 및 커머스 백엔드의 역할·지원요건·면접 관점이 포함된 실제형 샘플을 제공합니다. 예시 버튼에는 짧은 이름만 표시하고 선택 시 전체 문장을 입력합니다.
- 확장 화면의 추천 입력·결과·대기 패널은 공통 페이지 콘텐츠 폭을 사용해 헤더와 좌우선을 맞추고 `/recommend` 안에서만 16px 모서리·무그림자 큰 표면을 사용하며, 별도의 920px 최대 너비로 좁히지 않습니다. 내부 입력·Gallery·오류 경계는 유지합니다.
- 결과 생성 성공 시 자동 저장하고, 저장 실패 시 성공 결과로 표시하지 않습니다.
- 실행 CTA는 `AI 분석`으로 표시하고 활동 상세의 `다시 분석하기`와 동일하게 `AI 분석 결과`, `수정`, `삭제` 계열의 44px 높이·12px 모서리·여백의 흰색 액션 프레임을 사용합니다. 추천 화면만의 검은 prominent override는 두지 않습니다. 주황색·보라색 animated gradient는 1px 테두리, 텍스트, 기존 Sparkles 아이콘과 오른쪽 Chevron stroke에 함께 적용하며 pill 형태·inset shadow·세로 구분선은 사용하지 않습니다. reduced motion에서는 gradient와 Chevron 이동을 정지합니다.
- 추천 API와 저장 데이터의 `필수 역량`, `키워드`, `제약`, 기존 1순위 요약 필드와 참고 문장은 하위 호환을 위해 유지하되 현재 추천 결과와 추천 기록 상세에는 표시하지 않습니다. 답변 초안 본문 복사 기능은 유지합니다.
- 자기소개서 답변 생성은 300자 / 500자 / 1000자 프리셋과 `직접 입력`을 제공합니다. 직접 입력은 지원서의 최대 글자 수를 100~2000자 사이에서 정수로 받고, 수정 여백을 남기기 위해 입력값의 약 88~95% 분량으로 생성·검증합니다. 목표 제한과 실제 생성 범위는 대기 화면과 저장된 초안에 유지하며, 700자·1500자처럼 기업별 문항 제한을 그대로 입력할 수 있습니다.
- 현재 추천 결과는 추천 기록 상세와 같은 위계를 사용합니다. 텍스트 및 텍스트와 이미지 혼합 자기소개서·면접·기타의 짧은 질문과 240자 이하 JD는 저장 문장을 대표 제목으로 유지합니다. 이미지 단독 자기소개서는 위의 짧은 의도·핵심 키워드·기본 제목 순서를 적용하고, 240자를 넘는 JD는 추출 의도가 100자 이하이면 해당 의도, 아니면 `JD 요구사항과 경험 적합도 분석`을 제목으로 표시합니다. 긴 JD 원문은 헤더 아래 기본 접힘 `입력한 JD 보기`에 글자 수와 함께 보존하고, 펼친 내용은 최대 360px(640px 이하 280px) 안에서 독립 스크롤합니다. 추천 경험명은 Top 3 Accordion에만 두고, 특정 경험의 활동 기간·역할 메타와 하단의 중복 질문 구획은 표시하지 않습니다. 활용 목적·요구사항 분석·Top 3 근거·답변 생성 기능은 그대로 유지합니다.
- 완료 경험은 없지만 진행 활동이 있으면 오늘의 기록에서 먼저 완료 경험으로 정리하도록 안내합니다.

### 10. CampusLog AI - 추천 기록 (`/recommend/history`)

**목적**

이전 추천의 활용 목적, 질문, 추천 경험과 근거를 다시 확인합니다.

**핵심 요소와 동작**

- 헤더의 `새 추천 받기` 액션으로 추천 입력 화면에 돌아갈 수 있습니다.
- 좌측 메뉴와 중복되는 `CampusLog AI` eyebrow는 표시하지 않습니다.
- 페이지 H1 `추천 기록`과 `저장한 질문과 추천 경험을 다시 확인할 수 있습니다.` 설명은 목록 Glass 밖의 공통 헤더에 표시합니다. H1은 나의 활동과 같은 최대 1120px `primary-page` 프레임·반응형 gutter·공통 글자 크기와 y축을 사용합니다. 목록 Glass는 H2 `전체 기록`, 추천 기록 개수와 같은 차콜 Gooey 검색부터 시작해 페이지 제목과 탐색 섹션을 구분합니다.
- 선택 전 목록 Glass는 나의 활동처럼 가용 workspace 폭을 채우고, 기록을 선택하면 데스크톱에서 왼쪽 목록이 360px(중간 폭 300px)로 줄어들며 오른쪽에 같은 높이의 상세 Glass가 나타납니다. 선택 행은 옅은 차콜 틴트·왼쪽 인디케이터·굵은 제목으로 표시하고 닫기·Escape 뒤에는 실행한 행으로 초점을 복귀합니다. 860px 이하에서는 목록 다음에 상세를 세로로 배치합니다.
- 추천 기록 목록과 우측 상세는 나의 활동과 같은 stable 10px 채널·3px transient thumb를 사용합니다. 외곽 Glass는 overflow를 숨기고 목록과 상세의 내부 viewport만 스크롤하며, 실제 스크롤 중에만 thumb가 나타나고 650ms 뒤 숨습니다. 상세 viewport는 외곽 위·아래 30px 안쪽에 두어 둥근 모서리와 겹치지 않게 합니다.
- 각 추천 기록의 테두리·배경 없는 44px 채움형 별을 선택하면 노란색으로 바뀌고 해당 기록이 `즐겨찾기` 구획으로 이동하며 나머지는 `모든 기록` 아래에 유지됩니다. 첫 즐겨찾기가 생길 때만 두 구획 heading을 표시하고 해제하면 연한 회색 별과 원래 기록 순서로 복귀하며 항목을 복제하지 않습니다.
- 기록 본문 선택과 별 토글을 분리하고 별에는 `aria-pressed`, 추천 경험 제목을 포함한 추가·제거 이름, 저장 중 비활성 상태와 focus-visible을 제공합니다. 즐겨찾기에는 추천 id·선택 시각만 로그인 사용자의 `favorite_items`에 저장하고 화면 재진입·재활성화 시 계정 값을 다시 읽으며 추천 원문·결과는 변경하지 않습니다.
- 목록을 유지한 추천 상세는 목록과 같은 54% frosted Glass·28px blur 외곽 한 면을 사용하고, 내부 임베디드 결과는 투명하게 표시해 이중 테두리·그림자를 만들지 않습니다. 헤더는 중복 `AI 기반 활동 추천 결과` kicker 없이 추천 생성일·닫기 도구와 짧은 질문·문항을 대표 제목으로 표시하며 첫 추천 경험에만 연결되는 `활동` 도구는 표시하지 않습니다. 단, 이미지 단독 자기소개서는 짧은 분석 제목으로 정리하고 240자를 넘는 JD는 짧은 분석 제목과 기본 접힘 원문 disclosure로 분리합니다. 추천 경험명은 Top 3 Accordion에서 확인하고 특정 추천 경험에만 해당하는 활동 기간·역할은 상단에 중복 표시하지 않습니다. 활용 목적·분석 구획은 투명 배경과 hairline으로 나누고 제목 또는 disclosure로 이동한 질문·문항은 하단에 중복 표시하지 않습니다. 추천 경험은 회전 화살표가 있는 단일 펼침 Accordion으로 표시하고 1순위만 기본 펼침 상태로 둡니다. 닫힌 행에는 순위·한 줄 경험명·적합도만 남기고 추천 이유·직접 근거·부족 근거·과장 주의점·활용 각도·초안 생성은 펼친 영역에서 확인합니다. 각 펼침 영역에는 해당 경험 id로 이동하는 `활동 보기`를 두며, 사용자가 경험을 펼치면 높이 전환이 끝난 뒤 해당 행을 우측 상세 패널의 읽기 시작 여백에 맞춰 스크롤합니다. reduced motion에서는 이동 애니메이션을 생략합니다. 상세 안의 근거 정보는 패널 폭과 관계없이 1열로 읽히게 합니다.
- 추천 경험별 원본 활동 이동과 문장 복사
- 기록이 없거나 검색 결과가 없을 때 서로 다른 빈 상태와 다음 행동을 제공합니다.

### 11. 로그인 (`/` 인증 영역, `/login` fallback)

**목적**

기존 계정의 세션을 만들고 보호 화면 또는 원래 목적지로 이동합니다.

**필수 UI**

- CampusLog 브랜드와 로그인 제목
- 이메일과 비밀번호 입력
- 로그인 Primary CTA
- `또는` 구분 뒤 `Google로 계속하기`
- 회원가입 전환 링크
- 인증 중, 입력 오류, 인증 실패, 요청 제한과 네트워크 오류 상태

**동작 원칙**

- 입력값이나 계정 존재 여부를 오류 문구로 과도하게 노출하지 않습니다.
- 잘못된 자격 증명·가입 실패 같은 인증 오류는 Supabase 원문을 그대로 노출하지 않고, 계정 열거를 막는 공통 사용자용 오류 코드와 문구로 매핑합니다.
- 성공 시 안전한 보호 화면 `returnTo`가 있으면 해당 경로로, 없으면 `/`의 3D 책 표지로 이동합니다.
- 이미 로그인한 사용자가 `/login`에 접근하면 안전한 `returnTo` 또는 `/`의 책 표지로 연결합니다.
- Google OAuth 외 추가 소셜 로그인, 비밀번호 재설정과 이메일 확인 UI는 세부 정책 확정 전 추가하지 않습니다.

### 12. 회원가입 (`/` 인증 영역, `/signup` fallback)

**목적**

새 계정을 만들고 필요한 인증 절차를 거쳐 CampusLog를 시작합니다.

**필수 UI**

- 로그인과 같은 카드 위치·입력 순서의 `회원가입` 제목, 이메일과 비밀번호 입력
- 이메일 `회원가입` Primary CTA, `또는`, `Google로 회원가입`
- 이메일·Google 공통 이름 → 닉네임 2단계 Stepper
- 이름은 1~40자, 닉네임은 1~20자이며 앞뒤 공백을 제거하고 연속 공백을 정규화
- 이름의 계정 식별·개인화 목적과 닉네임의 비공개 사용 범위 안내
- 약관 동의가 필요한 경우의 명확한 필수·선택 구분
- 회원가입 Primary CTA
- 로그인 전환 링크
- 단계별 이전·다음, 제출 중, 입력 유효성 오류, 사용자용 가입 실패, 인증 대기와 성공 상태

**동작 원칙**

- 수집하는 개인정보와 사용 목적을 필요한 범위에서 안내합니다.
- 이메일 가입은 자격 증명을 클라이언트 메모리에서 단계 이동 동안만 보존하고 URL, localStorage, DOM hidden input, 로그에는 저장하지 않습니다. 최종 제출 직전에만 `FormData`에 넣어 이름·닉네임과 함께 Supabase signup 요청을 보내며 서버 응답 후 비밀번호를 비웁니다.
- Google OAuth callback은 로그인·가입 query가 아니라 교환된 실제 계정의 완료 metadata를 확인합니다. 미완료 계정은 `/onboarding`으로 이동하고, provider가 준 이름은 수정 가능한 초기값으로만 사용하며 닉네임은 사용자가 직접 확인·입력합니다.
- 이름·닉네임은 `user_metadata.campuslog_profile`에 비공개 최소 계정 정보로 저장합니다. 사용자 수정 가능 metadata이므로 RLS·권한 판단에는 사용하지 않으며 닉네임 고유성·검색·공개 프로필은 제공하지 않습니다.
- 미완료 계정은 온보딩에서 이탈해 `/`, 인증 fallback, 보호 화면에 접근해도 다시 `/onboarding`으로 이동합니다. 기존 계정에 완료 metadata가 없으면 최초 1회 입력을 요구하고, 온보딩 중 세션 만료 오류에는 `returnTo`를 보존한 재로그인 CTA를 제공합니다.
- 가입 실패도 계정 존재 여부를 직접 확인해주지 않는 공통 사용자용 오류 code와 문구를 사용합니다.
- 가입 직후 세션을 만들지 추가 인증을 요구할지는 인증 정책에서 확정합니다.
- 가입 즉시 세션과 프로필 저장이 완료되면 안전한 `returnTo` 또는 `/`의 3D 책 표지로 이동하고, 이메일 확인이 필요하면 확인 전까지 책 표지를 노출하지 않습니다.
- 각 단계 변경 후 현재 단계에 초점을 이동하고, 오류 시 첫 invalid 입력에 초점을 둡니다. 이름·닉네임 단계에서 이메일·비밀번호 입력으로 돌아가는 보조 액션은 모호한 `이메일 정보` 대신 `가입 정보 수정`으로 표시합니다. 320px 폭과 200% 확대에서 가로 잘림 없이 입력값과 오류 문구를 유지합니다.
- 로그인·회원가입 첫 카드는 32px 모서리·92/84% 쿨 표면·36px blur를 공유하고 입력은 54px·16px 모서리, Primary·Google CTA는 54px 완전 capsule을 사용합니다. 두 CTA는 hover에서 위로 움직이지 않고 밝기·테두리·얕은 그림자만 바뀝니다. 회원가입 진입 시 별도 방식 선택 버튼을 렌더링하지 않습니다.
- 이메일 확인 대기 상태는 일반 성공 feedback과 별도 보조 알림을 함께 렌더링하지 않습니다. 이메일 확인 아이콘과 단일 핵심 안내, `로그인으로 이동` 54px Glass capsule만 표시하고 기존 `이미 계정이 있다면 로그인` 문구는 숨깁니다.

### 13. 로컬 데이터 이전 안내 (Deferred / Optional)

현재 정식 범위에서는 신규 사용자가 계정별 DB부터 시작하므로 이 화면을 필수로 구현하지 않습니다. localStorage 원본은 자동 이전하거나 자동 삭제하지 않으며, 로그인 세션에서는 계정 DB 데이터를 기본으로 사용합니다.

**표시 조건**

향후 실제 기존 사용자 데이터 보존 요구가 생기고 이전 기능을 별도 승인한 경우에만 표시합니다.

**필수 정보와 액션**

- 발견된 데이터 종류와 개수
- 번들 샘플·개발 fixture·파싱 실패 항목을 제외한 실제 이전 가능 개수와 필요 시 제외 사유
- 현재 계정으로 이전된다는 설명
- 서버 데이터가 있을 때 자동 덮어쓰지 않는다는 안내
- 사용자의 명시적 이전 시작 액션
- 나중에 결정할 수 있는 비파괴적 보류 경로
- 진행률 또는 현재 처리 단계
- 성공, 일부 실패, 전체 실패와 재시도 결과

**안전 원칙**

- 안내 없이 자동 이전하거나 로컬 데이터를 삭제하지 않습니다.
- 이전 성공 여부를 항목별로 검증하기 전 원본을 제거하지 않습니다.
- 중복·충돌 해결 방식과 이전 완료 뒤 보관 기간은 DB 담당과 합의 후 문구와 액션을 확정합니다.
- 오프라인 fallback을 지원할지 결정되기 전에는 로컬 저장이 자동 동기화된다고 표현하지 않습니다.

### 14. 세션 만료와 재인증 상태

**필수 동작**

- 세션이 만료되면 이유와 재로그인 필요성을 알립니다.
- 현재 경로를 안전하게 보존해 로그인 후 복귀할 수 있게 합니다.
- 작성 중 입력은 가능한 한 브라우저 메모리나 합의된 fallback에 보존하고 즉시 폐기하지 않습니다.
- 보존할 수 없는 민감 정보는 예외이며, 어떤 정보가 사라지는지 제출 전에 안내합니다.

## AI 분석·추천 고도화 화면 원칙

- 다음 AI 기능 순서는 AI API 보호, AI 분석 품질 개선, 목적 / JD / 질문 기반 추천, 부족 경험 비교와 답변 초안입니다.
- 기존 분석과 추천의 최소 출력 계약을 제거하거나 의미를 바꿀 때는 화면, API 타입과 기존 저장 데이터 호환 계획을 함께 갱신합니다.
- 분석·추천 요청에는 `대기 → 처리 중 → 성공 또는 실패 → 재시도` 상태가 있어야 합니다.
- 결과에는 어떤 활동 또는 기록을 근거로 했는지 사용자가 이해할 수 있는 연결 정보를 제공합니다.
- 활동 종료 AI 초안은 자동으로 완료 경험에 확정하지 않고 계속 사용자 확인과 수정을 거칩니다.
- AI가 판단할 근거가 부족하면 내용을 지어내지 않고 부족한 정보를 표시합니다.
- 고도화 결과는 로그인 사용자 소유의 DB 데이터로 저장하며, 저장이 확인되기 전 완료 상태로 표시하지 않습니다.
- 호출 제한·입력 상한·중복 요청 오류는 공통 사용자용 error code로 처리하고, `retryAfter`가 있으면 재시도 가능 시점을 표시하며 입력을 보존합니다.
- 활동 종료 합성에도 같은 인증·호출 제한을 적용하고, 초안·실패·재시도 상태를 원본 활동 소유자에게만 표시합니다.
- 추천 후보 수, 비교 UI, 개인화, 사용자 피드백, 스트리밍, 생성 중 취소와 결과 버전 표시는 AI 담당의 계약이 확정된 뒤 설계합니다.

## 디자인·UX 작업 경계

### 디자인·UX 담당이 주도하는 항목

- v1.1 전 화면의 정보 위계, 간격, 타이포그래피, 표면과 인터랙션 고도화
- 데스크톱·모바일 반응형, 키보드 탐색, 초점, 대비와 reduced motion
- 로그인, 회원가입, 데이터 이전, 저장·동기화와 AI 상태의 이해 가능한 문구와 피드백
- 사용성 개선을 위한 탐색 구조 제안과 검증

### 계정·데이터·AI 담당이 제공해야 하는 계약

- 인증 상태, 세션 만료, 권한 오류와 경로 보호 동작
- 데이터별 조회·저장·삭제·마이그레이션 상태와 오류 코드
- AI 입력 한도, 처리 상태, 출력 필드, 근거, 저장, error code, `retryAfter`와 재시도 정책

### 공동 검토가 필요한 변경

- 화면에서 사용하는 데이터 필드와 API 응답 변경
- 인증 경로, 보호 범위와 `returnTo` 동작 변경
- 로컬·서버 충돌 해결, 오프라인 fallback과 삭제 정책
- AI 추천 후보 수나 결과 구조처럼 화면 레이아웃을 크게 바꾸는 기능

각 담당은 자신의 작업을 위해 다른 영역을 임의로 확정하지 않습니다. 미확정 항목은 로딩·빈 상태·오류 상태 계약과 함께 먼저 문서화한 뒤 구현합니다.

## 2차 MVP 화면 완료 기준

- 로그인, 회원가입, 로그아웃, 보호 경로와 세션 만료 상태를 모바일·데스크톱에서 완료할 수 있습니다.
- 로컬 데이터가 있는 사용자는 명시적 안내와 동의 후 이전하고 실패 시 재시도할 수 있습니다.
- 저장 성공·실패와 동기화 상태를 사용자가 구분할 수 있으며 입력을 불필요하게 잃지 않습니다.
- 기존 오늘 기록, 활동 종료, 나의 활동, AI 분석과 추천 화면이 사용자별 DB 데이터로 동작합니다.
- AI 고도화 결과가 근거와 저장 상태를 포함하고 기존 핵심 결과와 호환됩니다.
- 인증과 데이터 접근을 포함한 주요 흐름이 키보드, 초점, 대비와 reduced motion 기준을 충족합니다.
