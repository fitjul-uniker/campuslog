저장소의 활성 개발 단계 문서는 현재를 `2차 MVP`로 표시한다. 이 제출 문서에서는 1차 MVP의 핵심 흐름에 현재 `main`에 실제로 반영된 인증·DB·AI 고도화까지 포함한 결과물을 **UNIKER 중간 데모용 1차 프로토타입 스냅샷**으로 정리한다. 코드·자동 검증과 함께 프로젝트 책임자가 확인한 실제 Supabase·Vercel production 사용 상태를 구현 판단 근거로 사용한다.

기능 상태는 다음 의미로 사용한다.

- `구현 완료`: 현재 코드에 사용자 흐름이 연결되어 있고 정적 검사·테스트 또는 기록된 브라우저 검증 근거가 있다.
- `부분 구현`: 주요 동작은 존재하지만 일부 하위 기능이나 상태 처리가 아직 화면에 완전히 연결되지 않았다.
- `구현 예정`: 현재 화면 또는 동작 코드가 없고 후속 작업으로 기록되어 있다.
- `MVP 범위 제외`: 현재 중간 데모의 핵심 검증 범위에 포함하지 않는다.

## 2. 서비스 개요

### 서비스 한 줄 소개

대학생이 흩어진 활동 경험을 기록하고, AI 분석과 질문 기반 추천을 통해 자기소개서·면접·지원 준비에 다시 활용하도록 돕는 성장 기록 서비스다.

### 해결하려는 문제

- 프로젝트, 공모전, 인턴, 대외활동에서 한 일과 성과가 시간이 지나며 사라진다.
- 지원 문항이나 면접 질문을 받았을 때 어떤 경험을 골라야 할지 판단하기 어렵다.
- 경험을 기록해도 STAR 구조, 직접 근거, 부족한 정보가 정리되지 않아 다시 활용하는 데 시간이 든다.
- 기록에 없는 성과를 과장하지 않으면서 지원 목적에 맞게 내용을 재구성할 도구가 부족하다.

### 핵심 타깃 사용자

- 프로젝트·공모전·인턴·대외활동 경험을 쌓고 있는 대학생
- 자기소개서, 면접, JD 분석, 포트폴리오·지원서 준비를 앞둔 취업 준비생
- 현재 활동의 과정을 날짜별로 남기고 완료 후 하나의 경험으로 정리하려는 사용자

### 서비스가 제공하는 가치

1. 진행 중 활동과 완료 경험을 한곳에 보존한다.
2. AI가 경험을 요약·STAR·성과·키워드로 구조화한다.
3. 기록에서 부족한 정보를 질문으로 제시하고 답변을 후속 추천에 반영한다.
4. 사용 목적과 실제 질문을 기준으로 적합한 경험 최대 3개와 추천 근거를 비교한다.
5. 사용자 원본과 AI 결과를 분리해, 기록에 없는 사실을 임의로 추가하지 않는 활용 흐름을 제공한다.

## 3. MVP 목표

### 검증하려는 핵심 가설

- 대학생은 경험을 단순 보관하는 것보다, 지원 상황에서 다시 꺼내 쓸 수 있을 때 기록의 가치를 더 크게 느낀다.
- 원본 경험을 AI가 구조화하고 부족한 근거를 알려주면 사용자는 자신의 경험을 더 구체적으로 이해할 수 있다.
- 질문이나 JD와 경험을 함께 비교하면 사용자는 어떤 경험을 선택해야 하는지 더 빠르게 판단할 수 있다.
- 추천 이유와 직접 근거를 함께 제시하면 단순한 “AI 추천”보다 결과를 신뢰하고 수정해 활용하기 쉽다.

### 핵심 사용자 행동

1. 로그인 후 진행 활동 또는 이미 끝난 경험을 기록한다.
2. `나의 활동`에서 경험을 조회·수정하고 AI 분석을 실행한다.
3. AI가 제시한 부족 정보 질문에 사용자가 직접 답한다.
4. `AI 기반 활동 추천`에서 활용 목적과 질문 또는 JD를 입력한다.
5. 추천 경험 Top 3, 추천 이유, 직접 근거, 부족 정보와 활용 방향을 확인한다.
6. 필요하면 추천 기록을 다시 열거나 선택한 경험으로 답변 결과물을 생성한다.

## 4. 핵심 사용자 시나리오

### 시나리오 A. 이미 끝난 경험 기록과 AI 분석

1. 사용자가 로그인한다.
2. `나의 활동`에서 `과거 경험 기록하기`를 선택한다.
3. 제목, 기간, 역할, 내용, 성과와 관련 링크를 입력해 저장한다.
4. 저장된 완료 경험 상세 또는 `나의 활동` 인라인 상세에서 `AI 분석 요청`을 실행한다.
5. AI가 요약, STAR, 주요 성과, 부족 정보 질문과 키워드를 반환한다.
6. 화면은 분석 결과를 저장하고 다음 방문에도 다시 보여준다.

### 시나리오 B. 부족 정보 보완

1. 사용자가 분석 결과의 `부족 정보` 질문을 연다.
2. 실제로 기억하거나 확인할 수 있는 내용을 답변한다.
3. 답변은 원본 경험을 자동 수정하지 않고 별도 보완 정보로 저장된다.
4. 새 추천과 답변 생성은 저장된 보완 답변을 즉시 참고한다.
5. 요약과 STAR까지 갱신하려면 사용자가 명시적으로 `다시 분석하기`를 실행한다.

### 시나리오 C. 질문 기반 경험 추천

1. 사용자가 `AI 기반 활동 추천`으로 이동한다.
2. `면접 / 자기소개서 / JD 분석 / 기타` 중 활용 목적을 선택한다.
3. 질문·문항·JD를 텍스트로 입력한다. 선택적으로 JPG·PNG·WebP 캡처 이미지를 최대 3장 첨부할 수 있다.
4. 화면이 저장된 완료 경험과 분석·보완 답변을 선별·압축해 Next.js API Route로 보낸다.
5. AI가 적합한 경험을 최대 3개 추천하고 추천 이유, 직접 근거, 부족 정보, 과장 주의점과 활용 방향을 제공한다.
6. 추천 결과는 자동 저장되며 `추천 기록`에서 다시 확인한다.

### 시나리오 D. 진행 활동을 완료 경험으로 전환

1. 사용자가 `오늘의 기록`에서 활동을 추가한다.
2. 캘린더의 오늘 또는 과거 날짜에 실제로 한 일을 활동과 연결해 기록한다.
3. 활동을 종료하면 AI가 연결된 날짜별 기록만 사용해 완료 경험 초안을 만든다.
4. 사용자가 초안을 확인·수정한 뒤 `나의 활동`에 완료 경험으로 저장한다.
5. 생성된 완료 경험을 분석·추천 흐름에서 재사용한다.

## 9. 중간 데모 이후 개선 계획

### P0 — 핵심 시연 안정화

- 현재 정상 운영 중인 Vercel·Supabase·OpenAI production 버전을 데모 기준 버전으로 고정하고 직전 변경을 제한한다.
- 데모 전용 비민감 샘플 계정·경험·질문·JD를 준비한다.
- `경험 등록 → 분석 → 부족 정보 답변 → 추천 → 추천 기록` 시연 순서를 데스크톱·모바일에서 리허설한다.
- 외부 서비스 장애에 대비해 사전 생성 추천 결과, 핵심 화면 캡처와 대체 설명 순서를 준비한다.

### P1 — 추천 품질과 사용자 경험

- 사용자 선택형 정렬과 분석 상태·활동 상태 필터를 실제 `나의 활동` 화면에 연결한다.
- AI 추천·답변 생성의 대표 평가 문항과 기대 근거를 정해 반복 품질 검증을 자동화한다.
- durable rate limit, idempotency key, 서버 DB 재조회 기반 소유권 검증과 spend alert를 적용한다.
- 상세 로드 오류와 데이터 없음 상태를 분리하고 모든 핵심 실패에 명시적 재시도 경로를 제공한다.
- SQL 수준 RLS 테스트, 접근성 자동 검사와 실제 모바일 기기 E2E를 추가한다.

### P2 — 장기 확장

- 실제 기존 사용자 보존 요구가 생기면 동의 기반 localStorage 이전 기능을 구현한다.
- 이메일 확인·비밀번호 재설정·동일 이메일 provider 연결 정책을 확정한다.
- 오프라인 임시 저장과 재동기화, 추천 피드백, 개인화 기준을 검토한다.
- dependency advisory를 별도 브랜치에서 업데이트하고 인증·API·이미지 처리 회귀를 검증한다.
