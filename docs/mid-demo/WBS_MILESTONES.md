# CampusLog 1차 MVP WBS 및 마일스톤

> 이 문서는 UNIKER 1기 중간 데모 제출을 위해 현재 저장소의 문서와 실제 구현 상태를 기준으로 정리한 1차 MVP 스냅샷입니다.

## 1. 문서 개요

### 작성 목적

CampusLog가 문제 정의에서 시작해 경험 CRUD, AI 분석·추천, 인증·사용자별 저장과 UI 고도화까지 어떤 순서로 진행됐는지 보여주고, 중간 데모 시점에 완료·진행·미검증 영역을 구분한다.

### 일정 기준

- 프로젝트 기록 시작: 2026-06-25
- 현재 스냅샷: 2026-07-28 KST
- 기준 브랜치·commit: `main`, `3f4b1aa`
- 근거: Git commit·merge 기록, `docs/IMPLEMENTATION_PLAN.md`, `docs/WORK_STATUS.md`, `docs/TODO.md`, `docs/TASK_LOG.md`, `docs/ISSUE_LOG.md`
- 날짜는 저장소에서 확인되는 작업일 범위만 사용했다. 실제 회의일·근무 시간·투입 공수는 기록이 없어 임의 산정하지 않았다.
- production build는 2026-07-28 현재 다시 실행해 성공을 확인했다. 프로젝트 책임자 확인에 따라 실제 Vercel production 배포와 Supabase·OAuth·OpenAI 연동도 완료 상태로 반영했다.

### 상태 정의

| 상태 | 의미 |
| --- | --- |
| 완료 | 현재 코드 또는 문서 산출물이 존재하고 해당 단계의 핵심 완료 근거가 확인됨 |
| 진행 중 | 핵심 기능은 동작하지만 일부 UI 일관성, 자동 회귀 또는 후속 품질 작업이 남음 |
| 예정 | 아직 착수 근거가 없고 후속 작업으로 기록됨 |
| 보류 | 정책·의사결정·선행 조건을 기다리거나 우선순위에서 미뤄짐 |
| MVP 제외 | 현재 중간 데모 핵심 범위에 포함하지 않음 |

- 목적별 결과물 생성, 요청 상태 이벤트, 취소, 입력 선별·압축
